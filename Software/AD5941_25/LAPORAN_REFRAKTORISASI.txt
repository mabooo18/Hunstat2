LAPORAN PENGEMBANGAN DAN REFAKTORISASI
HUNSTAT2 / AD5941_25

1. RINGKASAN EKSEKUTIF
Proyek HunStat2 telah ditingkatkan dalam dua area besar:
1) Refraktorisasi firmware agar modular dan mudah dirawat.
2) Pengembangan UI Python untuk pengujian cepat (board nyata maupun dummy data).

Selain itu dilakukan investigasi mendalam terhadap jalur deteksi AD5941 (register read dan CHIPID)
untuk membantu diagnosis saat board tidak menampilkan data plot.


2. TUJUAN DAN RUANG LINGKUP
Tujuan pekerjaan:
- Merapikan struktur firmware agar setara pendekatan modular FreiStat.
- Memisahkan concern utama: setup hardware, command parsing, data storage, metode elektrokimia.
- Menyediakan UI test Python agar validasi firmware lebih cepat.
- Menambah mode dummy agar pengujian UI/plot tidak tergantung perangkat keras.
- Memastikan ada jalur troubleshooting untuk kasus AD5941 tidak terdeteksi.

Ruang lingkup pekerjaan:
- Folder firmware AD5941_25 (C/C++ Arduino).
- Folder python_ui (alat test desktop).
- Folder ad5941_register_test (uji register langsung).


3. HASIL REFAKTORISASI FIRMWARE
3.1 Prinsip arsitektur
Konstruksi lama cenderung monolitik. Setelah refaktor, arsitektur dipisah menjadi modul:
- setup: inisialisasi AD5941, reset, kalibrasi.
- communication: parsing serial dan dispatch perintah.
- data_storage: parameter dan state runtime.
- electrochemical_methods: implementasi OCP, EIS, CA, SWV, DPV, CV.
- interface/status: LED/NeoPixel dan utilitas indikator.

3.2 Manfaat teknis
- Kode lebih mudah dibaca dan diuji.
- Risiko perubahan silang antar fitur menurun.
- Penambahan metode baru lebih aman karena ada pemisahan per layer.
- Main sketch menjadi orkestrator, bukan tempat semua logika.


4. ALUR SISTEM FIRMWARE (SETELAH REFAKTOR)
1) Boot MCU.
2) Setup modul (resource MCU, reset, initialize AD5941, status LED).
3) Serial command diterima oleh communication layer.
4) Command diparse dan dipetakan ke metode (OCP/EIS/CA/SWV/DPV/CV).
5) Metode berjalan dan mengirim data hasil ke serial.
6) UI/host membaca data untuk plot/log.


5. PENGEMBANGAN UI PYTHON (HUNSTAT2 TEST UI)
5.1 Tujuan UI
Menyediakan tool cepat untuk:
- Connect/disconnect serial.
- Kirim command mentah.
- Atur parameter metode.
- Menjalankan metode terpilih.
- Menerima log serial dan plotting langsung.
- Export data CSV.

5.2 Fitur utama UI
- Panel koneksi serial (port, baud, refresh, connect/disconnect).
- Panel command dan parameter metode.
- Plot multi-mode dengan filter (ALL/OCP/EIS/CV/CA/SWV/DPV/NYQUIST/EIS_RAW).
- Load data dari log/csv.
- Dummy generator untuk uji visual.

5.3 Mode sumber data
Ditambahkan mode sumber data:
- BOARD: command dikirim ke perangkat nyata.
- DUMMY: command tidak dikirim; UI menghasilkan data sintetis.

5.4 Dummy data saat ini
Dummy disediakan untuk:
- EIS (termasuk Nyquist)
- CV
- CA
- SWV
- DPV
- OCP

Catatan penting:
Dummy data ditujukan untuk validasi alur UI/plot, bukan pengganti data eksperimen validasi ilmiah.


6. INVESTIGASI MASALAH PLOT KOSONG
Gejala awal:
- UI jalan, tetapi plot kosong saat metode dijalankan.

Temuan:
- UI hanya memplot baris data yang berhasil diparse.
- Pada beberapa kondisi, firmware hanya echo command atau mengirim format yang tidak sesuai parser plot.
- Akibatnya log ada, tetapi titik plot tidak bertambah.

Tindak lanjut:
- Parser UI diperluas agar mengenali beberapa format output serial.
- Ditambahkan mode dummy untuk memastikan plotting layer sendiri berfungsi.


7. INVESTIGASI AD5941 (REGISTER DAN CHIPID)
7.1 Tujuan
Memastikan jalur baca register AD5941 benar-benar bekerja di luar parser kompleks.

7.2 Keluaran investigasi
- Dibuat test script Python untuk kirim command register-read.
- Dibuat sketch Arduino terpisah untuk uji register langsung.
- Ditambahkan file pendukung lokal agar sketch test dapat dibangun lebih stabil di folder test.

7.3 Temuan teknis kunci
- Firmware publik HunStat2 memang memiliki command baca register (misal command I).
- Library resmi AD5940/AD5941 membaca CHIPID saat inisialisasi.
- Jika CHIPID tetap 0x0000/0xFFFF, indikasi kuat ke masalah hardware/SPI/reset/power,
	bukan semata masalah UI.


8. STATUS SWV, DPV, CA, OCP DUMMY
Selama iterasi, bentuk dummy beberapa metode disesuaikan beberapa kali mengikuti kebutuhan presentasi.
Status akhir mengikuti preferensi demo pengguna:
- SWV saat ini dikembalikan ke bentuk linear sederhana (garis lurus) sesuai permintaan terakhir.
- DPV/CA/OCP tetap tersedia dalam bentuk dummy untuk validasi alur plotting.

Implikasi:
- Untuk demonstrasi UI, bentuk ini cukup.
- Untuk demo ilmiah/metodologi elektrokimia, disarankan aktifkan profil dummy realistis
	atau gunakan data board nyata.


9. VERIFIKASI DAN BATASAN
9.1 Verifikasi yang berhasil
- Struktur modul firmware berhasil dirapikan.
- UI Python berjalan sebagai test console (serial + plot + export + dummy mode).
- Jalur diagnostik register AD5941 tersedia.

9.2 Batasan saat sesi pengembangan
- Toolchain Arduino penuh tidak selalu tersedia di environment ini.
- Karena itu validasi compile/upload final tetap perlu dilakukan di mesin pengguna
	(Arduino IDE/CLI dengan board core dan library lengkap).


10. PANDUAN DEMO UNTUK PRESENTASI
Skenario demo disarankan (5-10 menit):
1) Jelaskan masalah awal: monolitik + susah debug + plot kadang kosong.
2) Tunjukkan arsitektur baru modular.
3) Tampilkan UI test: mode BOARD vs DUMMY.
4) Jalankan Dummy All lalu filter per metode.
5) Tunjukkan command/register test sebagai jalur troubleshooting hardware.
6) Tutup dengan manfaat: maintainability, testability, diagnosability.

Talking points singkat:
- "Main sketch sekarang hanya orkestrator."
- "Setiap metode terisolasi, sehingga perubahan lebih aman."
- "UI test mempersingkat loop debug dari menit menjadi detik."
- "Jika CHIPID tidak terbaca, fokus ke hardware path, bukan parser UI."


11. REKOMENDASI LANJUTAN
Prioritas tinggi:
- Tambahkan profil dummy realistis yang bisa dipilih (Linear / Realistic / Noisy).
- Standarkan format output serial lintas semua metode agar parser UI lebih robust.
- Tambahkan timestamp dan metadata percobaan ke output CSV.

Prioritas menengah:
- Otomasi uji parser UI dengan sampel log.
- Tambahkan validasi parameter di firmware sebelum eksekusi metode.
- Dokumentasikan mapping pin dan checklist hardware AD5941 secara resmi.


12. KESIMPULAN
Refaktorisasi berhasil meningkatkan kualitas struktur software HunStat2 secara signifikan.
UI pengujian Python mempercepat validasi fitur dan memudahkan presentasi hasil.
Investigasi register AD5941 memberi jalur diagnosis yang jelas ketika data tidak muncul.

Secara keseluruhan, proyek sudah berada pada fondasi yang lebih kuat untuk:
- pengembangan fitur berikutnya,
- pengujian terstruktur,
- dan deployment yang lebih stabil di perangkat nyata.
